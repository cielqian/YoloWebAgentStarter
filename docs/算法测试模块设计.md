# 算法测试模块 — 端到端算法服务指标测试设计

> 设计基线：Ardot 原型「YoloWebAgent 算法训练平台」- 算法测试页（node 18:2，11 个 screen）。
> 范围决策确认于 2026-11-24。

## 1. 目标与已确认范围

对平台训练产出的模型，以**真实算法服务形态**（容器化 HTTP 服务，非本地推理）做端到端指标测试：

```
准备测试数据(含预期标记) → 部署算法服务 → 发起测试任务(逐张 HTTP 调用)
→ 解析响应 → 与预期标记匹配 → 计算指标 → 错误样本 → TP/FP 人工复核 → 回归对比
```

**已确认的边界决策：**

| # | 决策 |
|---|---|
| 1 | 图片分发：测试执行时把图片上传到配置的 FTP 目录，`{{image_url}}` 占位符替换为 **FTP 相对路径**，由算法服务侧自行从 FTP 取图 |
| 2 | 不做权限与审计 |
| 3 | 不支持 OCR；任务类型限定 平台已有四类：目标检测 / 图像分类 / 语义分割 / OBB 旋转框 |
| 4 | 测试数据集与训练数据集（`datasets`/`image_items`/`annotations`）**完全独立**，单独建表；标注工具在预期标记基础上增加 **TP/FP 人工复核** |
| 5 | 不做报告导出 |

**按差距分析补充的能力（本文档设计核心）：**
平台侧自研指标计算引擎（HTTP 结果 vs 预期标记）、延迟分位统计与预热剔除、任务参数快照、回归对比视图、GPU 资源互斥、服务生命周期完善（删除/升级/探活）、webhook 自动触发、异步回调协议预留。

## 2. 总体架构

新增后端模块 `backend/app/algorithm_test/`，前端新增 `AlgorithmTestView` 及子页面。与现有模块的关系：

```
algorithm_test (新)
├── 复用 app/ftp/service.py          upload/mkdir/fetch_directory_images → 图片分发与 FTP 同步建集
├── 复用 app/training/runtime/remote_nodes.py   compute-agent 协议(/devices /tasks)
│     └── 扩展 /services 端点(算法服务部署,恢复 algorithm_deploy WIP)
├── 引用 app/core/models.py ModelVersion   模型来源(训练产物/ONNX/OM)
├── 复用 frontend/src/annotation/AnnotationCanvas  预期标注 + 预测叠加复核
└── 不复用 训练数据集表结构 —— 独立 test_* 表
```

执行模型沿用现有模式：后台线程 + DB 状态机（参照 `YoloEvaluationRunner` / `local_compute_gate`），服务重启后孤儿任务回收。

## 3. 数据模型（9 张新表）

> P1 已落地(迁移 0040)。与下述草案的差异:几何列沿用训练 Annotation 的分离列结构(x/y/width/height/polygon/obb)而非 coords_json,便于复用标注前端与几何校验;标注排序加 sort_order;图片状态简化为 unmarked|marked(无 partial)。

```sql
-- 3.1 测试数据集
CREATE TABLE test_datasets (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  task_type TEXT NOT NULL,            -- detect | classify | segment | obb
  source TEXT NOT NULL,               -- local | ftp
  version TEXT NOT NULL DEFAULT 'v1', -- 数据集版本号,如 v1.2
  purpose_tag TEXT,                   -- regression | augment | hard | acceptance (可空)
  status TEXT NOT NULL DEFAULT 'ready', -- ready | annotating | locked(任务运行中)
  ftp_dir TEXT,                       -- 本测试集图片在 FTP 上的目录(执行时上传)
  notes TEXT,
  created_at/updated_at TIMESTAMP
);

-- 3.2 测试图片
CREATE TABLE test_images (
  id TEXT PRIMARY KEY,
  test_dataset_id TEXT NOT NULL REFERENCES test_datasets(id) ON DELETE CASCADE,
  file_name TEXT NOT NULL,
  storage_name TEXT NOT NULL,         -- 本地 managed storage 文件名
  width INTEGER, height INTEGER,
  ftp_path TEXT,                      -- 上传后的 FTP 相对路径,如 /ywa-test/{ds}/{name};空=未上传
  ftp_uploaded_at TIMESTAMP,
  status TEXT NOT NULL DEFAULT 'unmarked',  -- unmarked | marked
  source_checksum TEXT,               -- 上传内容 MD5,同数据集内去重
  point_id TEXT,                      -- 巡视点位 ID,替换 {{object_id}};可空
  created_at TIMESTAMP
);

-- 3.3 测试类别
CREATE TABLE test_class_labels (
  id TEXT PRIMARY KEY,
  test_dataset_id TEXT NOT NULL REFERENCES test_datasets(id) ON DELETE CASCADE,
  class_index INTEGER NOT NULL,
  name TEXT NOT NULL,
  color TEXT,
  UNIQUE(test_dataset_id, name)
);

-- 3.4 预期结果标注(ground truth) —— 几何结构与训练 annotations 同构
CREATE TABLE test_annotations (
  id TEXT PRIMARY KEY,
  test_image_id TEXT NOT NULL REFERENCES test_images(id) ON DELETE CASCADE,
  test_dataset_id TEXT NOT NULL,
  test_class_id TEXT NOT NULL REFERENCES test_class_labels(id),
  type TEXT NOT NULL,                 -- bbox | polygon | obb | classify
  x REAL, y REAL, width REAL, height REAL,
  polygon JSON, obb JSON,
  difficult BOOLEAN DEFAULT FALSE,    -- 难例标记:参与匹配但单列统计
  sort_order INTEGER DEFAULT 0,       -- 整图替换时的输入顺序,保证渲染顺序稳定
  created_at TIMESTAMP
);

-- 3.5 算法服务
CREATE TABLE algorithm_services (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  model_id TEXT NOT NULL REFERENCES model_versions(id),
  node_id TEXT NOT NULL,              -- 训练节点(compute-agent) ID
  host TEXT, port INTEGER,
  status TEXT NOT NULL DEFAULT 'creating', -- creating|starting|running|stopped|failed|deleting
  -- 调用与解析(Step1)
  request_config JSONB NOT NULL,      -- {method,url_template,headers,body_template}
  parse_config JSONB NOT NULL,        -- {root_path,label_path,score_path,bbox_path,bbox_format}
  -- 节点配置(Step2)
  deploy_config JSONB NOT NULL,       -- {base_image,container_name,container_port,start_cmd,
                                      --  health_timeout_s,restart_policy,gpu_device,
                                      --  response_mode: sync|callback, task_type_map:{detect:"bj_bpmh"}}
  container_id TEXT,
  last_health_at TIMESTAMP, last_health_error TEXT,
  created_at/updated_at TIMESTAMP
);

-- 3.6 测试任务
CREATE TABLE algorithm_test_tasks (
  id TEXT PRIMARY KEY,                -- T-2041 风格展示名由 id 派生
  name TEXT NOT NULL,
  service_id TEXT NOT NULL REFERENCES algorithm_services(id),
  test_dataset_id TEXT NOT NULL REFERENCES test_datasets(id),
  status TEXT NOT NULL DEFAULT 'queued', -- queued|preparing|running|computing|completed|failed|canceled
  progress INTEGER DEFAULT 0,         -- 已完成图片/总数*100
  params JSONB NOT NULL,              -- {confidence,iou,warmup_discard:3}
  snapshot JSONB NOT NULL,            -- 任务创建时的服务配置快照(request_config+parse_config+deploy_config+url)
                                      -- 服务事后被编辑不影响本任务的可复现性
  error TEXT, created_at/started_at/finished_at TIMESTAMP
);

-- 3.7 测试记录(任务完成后生成,一条任务一条记录,重跑生成新任务+新记录)
CREATE TABLE algorithm_test_records (
  id TEXT PRIMARY KEY,
  task_id TEXT NOT NULL REFERENCES algorithm_test_tasks(id),
  service_id TEXT NOT NULL, model_id TEXT NOT NULL, model_version TEXT,
  test_dataset_id TEXT NOT NULL, test_dataset_version TEXT,
  params JSONB NOT NULL,              -- 同任务.params(含 conf/iou)
  metrics_auto JSONB NOT NULL,        -- 自动匹配口径指标(见 §6)
  metrics_reviewed JSONB,             -- 人工复核后口径(复核完成时回填)
  latency_stats JSONB,                -- {mean,p50,p95,max,warmup_discarded}
  error_message TEXT,
  created_at TIMESTAMP
);

-- 3.8 每图结果 + 检测级复核
CREATE TABLE algorithm_test_image_results (
  id TEXT PRIMARY KEY,
  record_id TEXT NOT NULL REFERENCES algorithm_test_records(id) ON DELETE CASCADE,
  test_image_id TEXT NOT NULL,
  status TEXT NOT NULL,               -- ok | call_failed | parse_failed | skipped
  http_status INTEGER, error TEXT,
  latency_ms FLOAT,
  predictions JSONB NOT NULL,         -- 解析出的原始预测 [{label,score,bbox/polygon}]
  matches JSONB NOT NULL,             -- 匹配明细 [{pred_idx,gt_idx,iou,outcome:tp|fp|fn}]
  reviewed BOOLEAN DEFAULT FALSE      -- 本图是否完成人工复核
);

CREATE TABLE algorithm_test_review_marks (
  id TEXT PRIMARY KEY,
  record_id TEXT NOT NULL REFERENCES algorithm_test_records(id) ON DELETE CASCADE,
  image_result_id TEXT NOT NULL REFERENCES algorithm_test_image_results(id) ON DELETE CASCADE,
  target TEXT NOT NULL,               -- prediction(按 pred_idx) | match(按 gt_idx,即漏检)
  target_index INTEGER NOT NULL,
  mark TEXT NOT NULL,                 -- confirm_tp | confirm_fp | ignore | missed_confirm(确认识别为漏检)
  note TEXT, reviewer TEXT, created_at TIMESTAMP
);
```

迁移走 `core/migrations.py` 既有机制，与瀚高 PG 兼容口径一致（`JSONB`/`TIMESTAMP` 已有先例）。

## 4. 算法服务管理

### 4.1 配置（两步向导的后端化）

**Step 1 调用与解析 — `request_config` / `parse_config`：**

```jsonc
// request_config
{
  "method": "POST",
  "url_template": "http://{{host}}:20011/picAnalyse",   // {{host}} = 所选节点地址
  "headers": {"Content-Type": "application/json"},
  "body_template": {
    "requestHostIp": "{{host}}",
    "requestHostPort": "8088",
    "requestId": "{{request_id}}",
    "objectList": [{
      "objectId": "{{object_id}}",
      "typeList": ["{{type}}"],
      "imageUrlList": ["{{image_url}}"]
    }]
  }
}
// parse_config — JSONPath 绑定
{
  "root_path": "$.detections[*]",
  "label_path": "label", "score_path": "score",
  "bbox_path": "bbox", "bbox_format": "xyxy"   // xyxy | xywh_topleft | xywh_center
  // segment 服务若返回 polygon: "polygon_path": "polygon"
}
```

占位符规范：

| 占位符 | 取值来源 |
|---|---|
| `{{host}}` | 所选 Agent 节点 IP（部署后为服务实际 host） |
| `{{image_url}}` | 当前测试图片的 **FTP 相对路径**（§5.2） |
| `{{object_id}}` | `test_images.point_id`（巡视点位，建集/编辑时可填） |
| `{{type}}` | `deploy_config.task_type_map` 按数据集任务类型映射，如 `detect → bj_bpmh` |
| `{{request_id}}` | 每次调用自动生成的 UUID |
| `{{callback_url}}` | （异步模式预留）平台回调地址 |

渲染规则：逐张替换；占位符未匹配到值（如图片未填 point_id）→ **跳过该字段并在每图结果标记 `skipped_field`**，不中断任务。

**试跑校验（dry-run）**：`POST /services/{id}/dry-run`（或向导内 `POST /services/validate`）— 选一张测试集图片走完整链路（上传 FTP → 渲染请求 → 真实调用 → 解析 → 与该图预期标记比对），返回「命中 n / 漏检 n / 误检 n / 单图准确率」，向导第一步所见即后端真实结果。

**Step 2 节点配置 — `deploy_config`**：基础镜像（`YWA_ALGO_DEPLOY_BASE_IMAGES` 白名单，沿用 WIP 约定）、容器名、容器端口、启动命令、健康超时、重启策略、GPU 设备、`response_mode`。**启动预检**：镜像缓存 / 端口占用 / GPU 空闲 / 旧容器冲突（提示停止占用同端口的旧容器）。

### 4.2 部署执行（恢复未提交的 algorithm_deploy WIP）

`backend/app/algorithm_deploy/__pycache__` 中有完整 WIP（`AlgorithmDeploymentService`：Docker 部署、`common_service_onnx` 模板生成 `inferencer.py`/`response_builder.py`、ONNX/OM 双引擎、端口范围 `YWA_ALGO_DEPLOY_PORT_MIN/MAX`、agent `/services` 协议客户端）。实施第一步先反编译恢复源码（pyc 可恢复绝大部分），并入 `algorithm_test/services_deploy.py`。

compute-agent 侧新增端点（与 `/tasks` 同协议，`X-Agent-Token` 鉴权）：

```
POST   /services                 {deploy_dir_zip|payload, base_image, container_name,
                                  container_port, start_cmd, gpu_device, env} → {service_id}
GET    /services                 → [{service_id, container_id, status, port}]
POST   /services/{id}/start|stop
GET    /services/{id}/logs?after=0
DELETE /services/{id}
GET    /health                   → {convert_supported, services_supported, ...}
```

agent 收到部署包后：解压到工作目录 → `docker run -d --gpus device=... -p host_port:container_port --restart on-failure` → 健康探测（`health_timeout_s` 内轮询服务端口）→ 上报状态。平台侧 `DeploymentStatus` 与 `algorithm_services.status` 同步。

### 4.3 生命周期

- **启动/停止/日志**：代理 agent `/services`。
- **删除**：停止 → 删容器 → 删部署目录 → 删除 DB 记录（有关联测试记录时仅软提示，记录保留 metrics 快照不受影响）。
- **编辑/升级**：修改配置（含换模型版本）= 重新部署；历史测试任务因 `snapshot` 不受影响。
- **周期探活**：后台线程每 30s 对 running 服务做 TCP/HTTP 探测，更新 `last_health_at/status`；异常置 `failed` 并记录 `last_health_error`。

## 5. 测试任务执行引擎

### 5.1 状态机与队列

```
queued → preparing → running → computing → completed
   │         │          │
   └── canceled ←───────┘        任意阶段失败 → failed(error)
```

- **每服务串行**：同一 `service_id` 同时只允许 1 个非终态任务（DB 乐观锁 + 内存锁，参照 `local_compute_gate`），保证延迟指标独占性；不同服务可并行。
- 取消：置 `canceled`，执行线程在每张图间隙检查；已跑部分保留在 image_results，可由「重跑」以同参数新建任务。
- 重跑 = 以原任务 `params + snapshot` 新建任务（不覆盖原记录）。
- 孤儿回收：平台重启时 `running/preparing` → `failed("interrupted by restart")`，`queued` 重新入队（参照 `YoloEvaluationRunner.recover_orphaned`）。

### 5.2 图片 FTP 分发（决策 #1）

- 测试数据集建集时配置 `ftp_dir`（默认 `/ywa-test/{test_dataset_id}`，可改）。
- `preparing` 阶段：对 `ftp_path IS NULL` 的图片执行 `FtpService.upload(ftp_dir, file_name, data)`（`ftp/service.py:252`），成功后写回 `ftp_path = join(ftp_path_dir, file_name)` 与 `ftp_uploaded_at`。**幂等**：已有 `ftp_path` 的图跳过；上传失败重试 2 次（指数退避），仍失败则该图 `status=skipped(error="ftp_upload_failed")` 并继续。
- `{{image_url}}` 渲染为该相对路径（如 `/ywa-test/ds_ab12/IMG_0428.jpg`），算法服务侧用自身 FTP 配置取图。
- 任务全部结束后**不删除** FTP 文件（同一数据集反复回归免重传）；测试数据集删除时提供「同步清理 FTP 目录」选项。

### 5.3 逐张调用（running）

- 渲染 `snapshot.request_config`（占位符替换），`httpx` 调用，单张超时默认 30s（`deploy_config` 可配）。
- 同步模式（`response_mode=sync`，一期实现）：响应体按 `parse_config` 提取预测；HTTP 非 2xx / 解析异常 → 该图 `call_failed`/`parse_failed`，记录 error，**继续下一张**。
- 异步模式（`response_mode=callback`，二期实现，协议一期预留）：渲染时注入 `{{callback_url}} = {平台外部地址}/api/algorithm-test/callback/{image_result_id}`；平台收齐回调或超时后进入 computing。
- 每张记录 `latency_ms`（请求发出 → 响应完成）。
- 进度回写 `progress`；日志追加到任务日志文件（复用 `TrainingLogStore`）。

### 5.4 指标计算（computing）

对全部 `ok` 图片跑 §6 指标引擎 → 写 `metrics_auto` / `latency_stats` → 生成记录。

## 6. 指标计算引擎（`metrics.py`，自研核心）

### 6.1 匹配算法（检测类：detect/obb/segment）

对每张图，预测按置信度降序，与同类别的预期标注做 **greedy IoU 匹配**（与 Pycocotools 单图口径一致）：

```
for pred in sorted(predictions, key=score, desc):
    best_gt = argmax IoU(pred, 未匹配同类 GT)
    if IoU(best_gt) >= iou_threshold: TP(pred↔best_gt)
    else: FP(pred)
未匹配 GT → FN(漏检)
```

- IoU 口径：bbox 用轴对齐 IoU；obb/segment 有 polygon 时用多边形 IoU（复用 `models/error_samples.py` 的 `_polygon_iou`）；segment 无 polygon 时退化为 bbox IoU，并在记录中标注 `iou_basis: "bbox(fallback)"`。
- `difficult` 预期标注：参与匹配，但命中/漏检单独计数，不计入主指标。

### 6.2 指标输出（`metrics_auto` 结构）

```jsonc
{
  "iou_basis": "bbox|polygon",
  "overall": {            // 按 conf 阈值切片(point 指标)
    "precision": 0.914, "recall": 0.908, "f1": 0.911,
    "tp": 0, "fp": 0, "fn": 0,          // 计数
    "image_accuracy": 0.87,             // 无 FP 且无 FN 的图片占比
    "difficult": {"tp": 0, "fn": 0}
  },
  "map50": 0.872,                       // PR 曲线 all-point 插值(Ultralytics/COCO 口径)
  "map50_95": 0.615,                    // IoU 0.5:0.05:0.95 十档均值
  "per_class": [                        // 分类别
    {"class": "裂缝", "support": 148, "map50": 0.872,
     "precision": 0.921, "recall": 0.905, "f1": 0.913}
  ],
  "classify": {                          // 仅 classify 任务
    "top1_accuracy": 0.93, "top5_accuracy": 0.99,
    "macro_precision": 0.9, "macro_recall": 0.89, "macro_f1": 0.895,
    "confusion": [["23","1","0"], ...]
  },
  "error_samples": {                     // 错误样本分类(详情页直接渲染)
    "missed": [...],       // FN 漏检 {image, gt_class}
    "false_positive": [...], // FP 误检 {image, pred_class, score}
    "wrong_class": [...],  // 错类(IoU 达标但类别不一致的匹配对)
    "low_confidence": [...] // GT 命中但 score < conf 阈值
  }
}
```

- mAP 计算不依赖 `yolo val`：以全部图片的 (score, TP/FP) 汇总绘制 PR 曲线，all-point 插值求 AP（与 COCO 一致）；`conf` 参数决定 point 指标（P/R/F1）切片位置，不影响 mAP。
- 单元测试锚点：构造已知预测/GT（完全命中、全漏检、错类、分数排序影响 AP）验证引擎数值，与 Ultralytics val 结果对拍一组固定数据集。

### 6.3 延迟统计（`latency_stats`）

- 剔除前 `warmup_discard`（默认 3，任务参数可调）张（首张含模型加载/ JIT 预热）。
- 输出 `mean / p50 / p95 / max`（成功调用样本）；`call_failed` 不计入延迟但计入可用性（`ok_rate`）。

### 6.4 人工复核口径（`metrics_reviewed`）

复核标记（§7）生效后重算：`confirm_fp` 的预测从 TP 中剔除、`ignore` 的预测/GT 双侧剔除、`missed_confirm` 确认 FN。自动口径 `metrics_auto` 永远保留，详情页可切换「自动 / 人工复核」两个口径查看。

## 7. 预期标注 + TP/FP 人工复核（决策 #4）

测试数据集标注页 = `AnnotationCanvas` 的测试侧实例，两个模式：

**① 预期标记模式（任务前）**：画框/多边形/图级类别作为 ground truth（`test_annotations`）；类别来自测试类别库（新建/从类别模板导入）。检测/分割必须框级标注，分类为图级标签。图片列表带 全部/已标记/未标记 筛选与标注进度。

**② 结果复核模式（任务后）**：从测试记录详情进入，叠加显示该图预测（按 `parse_config` 解析的框/类别/分数）与预期标记：
- 每个预测可标记：`confirm_tp` / `confirm_fp` / `ignore`；
- 每个 FN 可标记：`missed_confirm`（确认识别为漏检）/ `ignore`（GT 画错了，双剔）；
- 支持直接在图上**补画预期框**（补录 GT → 提示"将提升数据集版本"，写入 `test_annotations` 并建议版本号 +0.1）；
- 复核完成后该图 `reviewed=true`；全部复核后回填 `metrics_reviewed`。

## 8. 回归对比

- 入口：测试记录历史多选 2 条（约束：任务类型一致）→ 对比视图。
- 内容：
  - 指标 delta：mAP50 / mAP50-95 / P / R / F1 / P95 延迟，逐项升降箭头；
  - 分类别 delta 表；
  - **错误样本集合运算**：两记录错误样本按图片求 交/差 → 「新增错误（回归）」「已修复」「仍然错误」三组样本列表——回归测试的核心读数；
  - 适用场景：同数据集比模型（v2 vs v3）、同模型比数据集版本（V1.0 vs V1.2 难度变化）。
- API：`POST /api/algorithm-test/records/compare {record_a, record_b}`，纯读端点实时计算。

## 9. GPU 资源互斥

- **部署占用登记**：`algorithm_services` running 且 `deploy_config.gpu_device` 非空时，该 (node, gpu) 从训练调度可用池排除 —— 扩展 `remote_node_occupied_devices`（`training/runtime/remote_training.py:373`）合并服务占用；agent 侧 `/devices` 的 `memory_free_mb` 同步反映容器占用（agent 实现侧扣除）。
- **测试任务独占**：§5.1 的每服务串行即保证测试期间无并发调用干扰延迟。
- 训练与测试可并存（不同 GPU/节点）；同 GPU 冲突时训练排队提示「被算法服务 xxx 占用」。

## 13. 测试策略

- **指标引擎单测（最重要）**：`metrics_test.py` 构造已知场景（完美匹配 / 全漏检 / 全误检 / 错类 / 分数边界 / difficult / polygon vs bbox 口径）断言 mAP/P/R 数值；一组固定小数据集与 Ultralytics `yolo val` 输出对拍。
- **模板渲染单测**：占位符替换、缺值跳过标记、`{{type}}` 映射。
- **匹配复用**：`error_samples.py` 的 IoU/polygon 工具抽出共用（避免两套口径）。
- **集成测试**：fake HTTP 服务（返回预置 JSON）驱动任务执行器全流程，含单张失败续跑、取消、重启恢复。
- **前端**：沿用 vitest + AntdApp 包裹模式，复核交互与对比视图重点覆盖。
